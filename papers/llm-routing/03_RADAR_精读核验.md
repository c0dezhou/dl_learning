# RADAR：不仅选哪个模型，还选让它思考多久

> 英文题名：**RADAR: Reasoning-Ability and Difficulty-Aware Routing for Reasoning LLMs**  
> 来源：[arXiv:2509.25426v3（英文原文）](https://arxiv.org/html/2509.25426v3)，**ICLR 2026** 会议论文。  
> 核验材料：库中 `radar.pdf` v3 的 §3–§4、附录 B/D，重点为 Eq.(4–9)、表 1–3、表 18、表 20–23。  
> 标签：**[原文]** 作者给出的定义/数字；**[推导]** 从公式分析得出；**[待实验]** 合理但尚未成立的问题。与之前讲稿不同，这份核验直接用了英文原文。

## 先说清楚它在解决什么新问题

假设一个推理模型可以选择“不思考直接答”“最多想 256 token”“最多想 4096 token”。同一个模型面对一道简单题，可能不用长篇思考也能答对；碰到难题则可能需要更长的思考预算。但预算越大，平均响应成本和时间也越高，有时过度思考还会降低效果。

**RADAR 认为路由选项应该是“模型 + 推理预算”的组合**，而不是单独的模型名。它先用教育测量学的 IRT 模型预测每个组合做对某题的概率，再把概率与估计费用合在一起选择配置。想象学校组织考试：不是只决定派哪位同学，还要决定给这位同学多少答题时间。

它最值得我们研究的另一点是：当新模型出现，**不是固定测一套题，而是看它前面答得怎样，决定下一题测什么**，用尽可能少的题估计其能力。但请注意：它优化的目标是**把能力估计准确**，并没有直接在选题公式里优化最终路由是否会换成更好的模型。

## ① 候选空间：为什么是 35，而不是 7？

[原文，§3.1、§4、附录 D.1]

| 底座模型 | 可用推理预算 | 形成的配置数 |
|---|---|---:|
| OpenAI `o4-mini` | low、medium、high | 3 |
| `Qwen3-0.6B` | 0、256、512、1k、2k、4k、8k、16k | 8 |
| `Qwen3-1.7B` | 同上 | 8 |
| `Qwen3-4B` | 同上 | 8 |
| `Qwen3-8B` | 同上 | 8 |
| **合计** | | **35** |

这不是 35 个相互独立的底座模型，而是 **5 个底座模型、35 种模型配置**。Qwen 的数值是思考 token 数量的上限，超过时插入中断指令与特殊 token，要求停止思考并输出答案；不是提前保证模型一定生成恰好 256/512 个思考 token。[原文，§3.1]

这项“改变决策对象”的贡献很实在：在相同底座下，RADAR 可以在“低预算/高预算”间切换。但也随之带来大量配置离散化选择问题：预算取点过稀可能错过合适范围，过密则采集成绩和建立配置档案成本上升。[推导]

## ② 题目表示：怎样知道什么题比较难？

[原文，§3.3、附录 D] 使用冻结的 `Qwen3-Embedding-8B` 把问题转换为 **4096 维向量** `e_q`，然后两个可学习的线性映射分别得到：

\[
 a_q=\mathbf w_a^{\top}\mathbf e_q,\qquad
 b_q=\mathbf w_b^{\top}\mathbf e_q.
\]

**a 是区分度，b 是难度，二者都是标量。**

通俗解释：`b_q` 越高，表示按这种统计建模这题所需能力越高；`a_q` 表示这道题能在多大程度上区分不同能力的配置。题目文本不是直接输入一个巨大的 LLM Router，而是经过 embedding 后压缩为两个数，再进入概率模型。

要小心：“可解释”是结构赋予变量的含义，不意味着预测出的 b 完全等于人类判断的难度。它仍依赖训练数据、文本编码器和 2PL 假设。

## ③ 模型表示：每个配置只用一个能力 θ

[原文，§3.3] 每个配置 `g` 有一个实数能力参数 `θ_g`，从“训练题 × 配置”的做题成绩中与题目参数联合学习，不需要模型名字或说明文字，也不靠参数量直接推断能力。

这里和 IRT-Router、ZeroRouter 很不同：

- **IRT-Router**：简介 → 25 维能力向量。
- **ZeroRouter**：测试数据 → 20 维能力向量。
- **RADAR**：测试数据 → **一个标量能力**。

**为什么一个数也有价值？** 如果题目主要沿着一条“总体难度轴”变化，一个数会很省参数、容易排序；但如果能力之间存在严重互补，例如 A 擅长代码、B 擅长数学，同一条轴可能无法很好表达“谁在哪些题上突出”。这属于**模型容量/假设上的可能局限 [推导]**，不能在没做对照前说 scalar IRT 必然不如多维。

**另一个问题 [推导]**：同一 Qwen 底座的不同预算作为独立配置学 θ。方法并没有把预算之间的依赖关系写成层次模型；因此即使所有配置共享底座，较少预算的数据也不一定被充分用于较大预算的能力估计。注意作者也讨论过“预算增大有时会过度思考”，不能机械要求能力随预算严格单调。

## ④ 答对概率：2PL 的核心公式

[原文，§3.3、Eq.(5)]

\[
\widehat P(y_{qg}=1)=\sigma\!\left(a_q(\theta_g-b_q)\right),
\qquad \sigma(z)=\frac{1}{1+e^{-z}}.
\]

逐字解释：如果配置能力 θ 比题目难度 b 大，且区分度 a 为正，括号里的值通常更大，预测答对的概率也更高。

**教学示例（非论文实测）**：一道题 `a=2`、`b=0.5`；某配置 `θ=1.0`，得到 `σ(2×0.5)=σ(1)≈0.731`；另一个配置 `θ=0`，得到 `σ(-1)≈0.269`。一个问题和一个配置之间，只需要这 3 个数就能算出预测概率。

[原文，Eq.(5)、附录 D] 从全部已知的配置—题目结果格子优化平均交叉熵，训练 100 epochs，学习率 `5×10⁻⁴`、batch size 32。正文没有在显示的线性映射式中给 `a` 一个明确的非负约束，因此“θ 越高一定越容易答对”的逐题数学单调性，**从印出的式子本身尚不能保证**；是否有未写出的实现约束，需要检查官方代码。[推导 + 待代码]

## ⑤ 成本：注意它不是按每道题预测输出长度

[原文，§3.4、Eq.(6)]

\[
\widehat C(g)=\frac{1}{|\mathcal Q_{train}|}\sum_{q\in\mathcal Q_{train}}
(n_{gq}^{reason}+n_{gq}^{answer})\,t_g.
\]

这里 `t_g` 是对应底座模型的输出 token 单价，思考 token 和作答 token 都纳入。把训练集里各题的实际输出长度求平均，就得到**该配置的一个平均输出成本常数**，然后对配置之间成本使用 min-max 归一化到 `[0,1]`。

**它不随当前题目变化，并且这个启发式公式没有计入输入 token 费用**。比如一条普通数学题与一条包含十几篇文章的长上下文题，若分配到同一配置，在路由打分时使用的是同一个配置成本估计。长上下文上的成本误差可能更值得检查；但要有实际逐题 token 数据才能确定影响程度。[原文 + 推导]

这也解释为什么不能把本文成本预测写成 ZeroRouter 式的“每题输入+输出长度估计”。二者明显不同。

## ⑥ 路由目标：RADAR 的 Chebyshev 到底改变了什么？

[原文，§3.2]

普通线性加权选择：

\[
 g^*(q)=\arg\max_g\left[w\widehat P(q,g)-(1-w)\widehat C(g)\right].
\]

RADAR 重点使用的加权 Chebyshev 标量化：

\[
 g^*(q)=\arg\min_g\max\left\{w\left|1-\widehat P(q,g)\right|,
(1-w)\widehat C(g)\right\},\qquad 0\leq w\leq1.
\]

**解释**：理想点是“正确率 1，成本 0”。线性式把质量和价格直接相加；Chebyshev 式看加权后最差的那一项，即“离理想目标差得最严重的维度”。改变 w 会走向不同配置。

原文强调线性加权可能找不到非凸 Pareto 前沿的某些离散点，而 Chebyshev 可以找到。要注意两层条件：

1. **作者论文的离散配置集合下**，这个论点有数学依据；并在 OOD 的附录表 18 进行了对比。
2. **若允许按概率随机混合配置**，期望成本—质量点会形成凸组合，那些不在上凸包的点可能不再是批量平均意义下的最优点。此时“能找到凹部点”不自动等于部署收益更高；需要明确用户到底要求单请求确定性约束还是长期平均预算。这是研究设计层面的**推导**，不是原文实验已证实的不足。

## ⑦ 新模型接入：最值得精读的“自适应考试”

[原文，§3.5，Eq.(7–9)] 新来一个配置，保留已经学到的题目 `a_q,b_q`，只估它自己的 θ。

**一轮过程**：

1. 先设置新配置当前能力猜测 `θ̂₀=0`；已测题集为空。
2. 对所有尚未测的题，计算当前 θ 下的 Fisher 信息：

\[
 I(q;\theta)=a_q^2\,p_q(\theta)[1-p_q(\theta)],
 \quad p_q(\theta)=\sigma(a_q(\theta-b_q)).
\]

3. 选择信息量最大的那道题，让新配置真实作答并获得对/错标签。
4. 用迄今已测的全部结果重新做最大似然估计，得到更新后的 `θ̂_t`。
5. 继续下一轮，直到预算用完。

**为什么 Fisher 最大不一定是“最难的题”？** 信息来自 `a² × p(1−p)`。假设区分度相同，一道估计有 50% 正确概率的题比几乎肯定做对/做错的题更能区别“能力究竟在哪个位置”。而区分度越大，通常更有信息，所以还要乘 `a²`。

[原文，§4.3、表 3、附录表 20–23] 加入 `Qwen3-14B` 的 8 档预算配置。主要新配置校准使用 **5000 道题，约训练集的 12%**；附录还比较 100、500、5000 道下 Fisher 选题与随机选题。**这 5000 道是校准一个新配置能力的采样规模，不能写成只花 5000 道就完成 8 个配置的全部评测。**

### 它真正优化什么？

- **显式的选题目标**：尽快减少 θ 的估计不确定性，即“测准这个配置的能力”。
- **最终报告的指标**：接入后的成本—质量路由曲线。
- **可能出现的错位 [推导]**：一个配置的 θ 被测得很准，但如果它在大多数题目上都比旧池已有配置贵且弱，那么路由收益仍可能几乎为零；反之某个新配置只在狭窄的低成本决策边界上有用，可能不必准确估计其全局能力。

这是“**能力估计最优** 不一定等于 **部署决策最优**”的候选研究问题。但要证明它是可投稿的 gap，必须在强基线上复现、检查新文献，并用相同预算的效用实验验证。

## ⑧ 评测：至少背下来这四个数字和条件

[原文，§4、表 1–3、附录]

**数据**：8 个推理基准，包括 GPQA-Diamond、MMLU、MMLU-Redux、MMLU-Pro、LSAT、AIME、MATH-500、FRAMES；一共 **50,139 个不同问题、约 175 万条二值回答记录**。ID 与 OOD 按基准划分，OOD 还考虑重叠数据的排除条件。常规问题/配置的输出评测一般只执行一次；**AIME 因测试题较少进行了多次运行**。所以旧稿“只跑一次”作为对整篇实验的判断不成立。

**评价指标**：

- **Hypervolume**：概括性能—成本前沿的覆盖面积，越大越好。它不是单个成本点的正确率；不同论文的归一化若不同，也不能直接跨论文比绝对数值。
- **CPT(90%)**：达到参考配置 `o4-mini/high` 平均性能的 90%，最少需要其多少比例的费用，越小越好。如果原模型准确率是 80%，目标是 72%，**不是 90% 的绝对准确率**。
- **Oracle**：使用测试时每题真实成绩事后选最佳配置，是理想上界，不是可部署方法。

**主表部分数据**：

| 场景与量 | 原文数字 | 正确解释 |
|---|---:|---|
| MATH-500，ID CPT(90%) | **1.31%** | 达到 o4-mini/high 质量的 90%，所需成本相对于它的比例 |
| FRAMES，OOD CPT(90%) | **9.99%** | 长上下文 OOD 场景下约十分之一的参考成本 |
| GPQA-Diamond，ID Hypervolume | RADAR **0.7513**，IRT 基线 **0.6942** | RADAR 在该指标、该设置下较好 |
| MATH-500，ID Hypervolume | **RouterBench 0.9528**，RADAR **0.9449** | **不是 RADAR 每个基准都第一** |
| 新增 Qwen3-14B，GPQA OOD Hypervolume | **0.7466 → 0.7463** | **略微下降**，不是接入后所有集合必增 |
| 新增 Qwen3-14B，FRAMES OOD Hypervolume | **0.8865 → 0.8931** | 有一定改善，但不能概括成普遍大幅提升 |

**附录表格核验提醒**：主表 1 的 ID MMLU RADAR 值是 **0.8720**、FRAMES 是 **0.8762**；附录表 20 标称“ID”的基线列却出现 MMLU **0.8609** 和 FRAMES **0.8865**，与主表不一致，后者还与表 3 的 OOD 基线数字一致。**原文内部存在表格口径不一致的疑点，引用主要结论时优先标清采用主表，不能私自将不同表的数混合。**

**实验成本与设备**：[原文，附录 D.2] 开源 Qwen 模型采用 `vLLM` 部署，每个模型用一张 **NVIDIA A100 80GB**；路由时延实验报告约 **6.89 ± 0.53 ms** 的附加时间。这意味着单卡 8GB 显存机器不适合按原方式从零生成全量 175 万条结果；**但不能因此说 RADAR 理论、选题公式或路由后处理不可复现**。可将“结果生成”与“利用公开缓存做方法复现”拆开评估；缓存是否完整开放还需单独核对。

## 候选破题点

**R-1 [原文+推导→待实验]：Fisher 估能力，未直接以路由后悔值选题。** 设计决策价值导向的主动测试（如 expected utility improvement、VoI），对比同预算 Fisher、随机、D-optimal 和难度分层。但要先检查收益是否可能被新模型“不值得接入”的情形冲淡。

**R-2 [原文→待实验]：每配置固定输出成本，长上下文与输出长度动态性未建模。** 用真实逐题输入/输出费用替换常数成本，测 Pareto 曲线和决策翻转；若收益主要来自费用而非能力预测，论文贡献应诚实说明。

**R-3 [推导→待实验]：同一底座不同预算没有共享能力结构。** 尝试层次先验或“底座能力 + 预算增量”共享统计强度，尤其在少量校准反馈下比较。但不能假设能力对预算严格单调，需要保留 overthinking 的例外。

**R-4 [原文→待实验]：未讨论在何时提前停测或拒绝接入。** 5000 是实验配置，不等于每个新模型都值得花足预算。先测试顺序停测策略是否能节省评测成本、且不损失后续部署收益；也要查后续 adaptive profiling 文献确认新颖性。

## 老师可能问

1. 为什么 5 个底座模型却有 35 个候选？因为路由决策对象是“模型与推理预算”的组合。
2. Fisher 选题是不是随机挑最难的？不是，它最大化在当前能力估计位置的信息量，考察区分度及不确定性。
3. 5000 是零样本接入吗？不是；新配置确实需要运行大量校准题，零样本不成立。
4. Hypervolume 好不代表所有用户都收益更好吗？是的；要结合预算偏好、Pareto 曲线和具体成本点。
5. 笔记中的 “deployment-aware profiling” 能否直接称创新？不能；当前只是候选问题，必须用强基线、文献排重与部署效用实验共同证实。
