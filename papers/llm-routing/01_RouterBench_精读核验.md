# RouterBench：一篇教你“怎么公平比较路由器”的论文

> 英文题名：**RouterBench: A Benchmark for Multi-LLM Routing System**  
> 来源：[arXiv:2403.12031v2（英文全文）](https://arxiv.org/html/2403.12031v2)，2024 年 3 月版本。  
> 核验依据：原文 §3–§5、图 2–6、附录 A、B。  
> 证据标记：**[原文]** 表示论文明确写出；**[推导]** 表示根据公式或设计推出；**[待实验]** 表示仍需要验证。文中“例子”均为教学示例，并非原文数据。

## 先用人话理解这篇论文

一家平台同时接入 GPT-4、Mistral、Claude 等模型。给用户一道题，如何证明你设计的路由器比“干脆选固定便宜模型或者昂贵模型”好？只报一个平均准确率不够，因为别人可能花了你 10 倍的钱；只报省钱也不够，因为可能牺牲了答题质量。

**RouterBench 的主要贡献不是发明一个很厉害的路由网络，而是提供一张可复用的“每道题 × 每个模型”的成绩和花费表，并定义如何公平比较质量—成本曲线。** kNN、MLP 和级联是用来演示和分析的路由算法。这一点与原笔记中将其主要当成 kNN/MLP 方法论文的表述不同。

阅读主线：原始题目与模型结果表 → 路由策略 → 每个策略的成本/质量点 → 取非递减凸包 → 在共同成本范围计算 AIQ → 对照 Zero router 与 Oracle。

## ① 候选空间：到底能选哪些模型？

[原文，§4.2–§4.3] **核心 11 个模型**：开源 6 个（Llama-70B-chat、Mixtral-8×7B-chat、Yi-34B-chat、Code Llama-34B、Mistral-7B-chat、WizardLM-13B），闭源 5 个（GPT-4、GPT-3.5-turbo、Claude-instant-v1、Claude-v1、Claude-v2）。**另有 3 个联网检索服务**（You.com API、Perplexity 的 sonar-small-online 和 sonar-medium-online），用于 RAG 场景。不能简单说“全部只有 11 个”，也不能说普通实验同时在 14 个里挑选。

[原文] 覆盖 8 个数据集：HellaSwag、Winogrande、ARC-Challenge、MMLU、MT-Bench、GSM8K、MBPP、RAG；包含 64 个任务、**405,467 条结果记录**。RAG 是 800 个带参考答案的检索相关用户问题。论文针对不同任务使用了不同的正确性评判方式；不要把 405,467 理解成 405,467 个互不重复的题目。

**重要解释**：模型候选池必须包含不同成本、不同长处的模型。如果所有模型能力完全相同，且价格相同，路由就没有收益空间。这个“收益空间”必须用 Oracle 与实际可实现方法区分。

## ② 题目表示：路由器怎样读懂输入？

[原文，§5.1] 论文展示两种*预测式*路由：

- **kNN**：给当前问题找训练集中最相似的 k 道旧题，参考这些题上各模型的表现。
- **MLP**：把题目的数值表示输入神经网络，预测每个模型可能取得的成绩。

**训练划分**：[原文，§5.3] 按任务随机分 **70% 训练、30% 测试**；MT-Bench 样本太少，未参加此预测式路由对比。

**原文未交代的细节**：正文没有明确统一指定哪一种 embedding 模型。不能自行把 BERT、Sentence-BERT 或其他具体编码器填进去。题目表示不是该论文的主要方法贡献。

## ③ 模型表示：怎样记录一个模型的能力？

[原文 + 设计解释] 这篇论文没有 IRT 那样的“模型能力向量 θ”。最直观的“模型档案”就是**它在训练题上的表现记录**：例如同一批数学题，模型 A 哪些做对、模型 B 哪些做对。kNN 依赖这些邻居成绩；MLP 则可以看成每个模型学习从题目到预期表现的预测器。

[推导] 好处是几乎不作强结构假设；限制是**新模型没有旧题上的结果时，不能凭空得到其预测性能**。但论文没有专门设计新模型接入实验，所以只能说“其展示的算法依赖成绩数据”，不能说作者证明了新模型必须全量重训。

## ④ 性能预测：对某道新题，猜谁能做好？

### kNN 的公式

对模型 m、题目 q：

\[
\widehat P_m(q)=\frac{1}{k}\sum_{q'\in NN_k(q)}y_{q',m}.
\]

举例：当前是数学推理题，最相近的 5 道训练题中，模型 A 答对 4 道、模型 B 答对 2 道。则两者的估计成功率分别是 **0.8** 和 **0.4**。这不是实际推理后得到的结果，而是历史相似题带来的预测。

### MLP 与级联不要混为一谈

**MLP** 不显式找邻居，它学习一个从题目特征到成绩的非线性函数；预测时不先调用所有候选模型。

**级联（cascading）** 则完全不同：[原文，§5.2] 先问便宜模型，用判断器 g 查看其回答是否满足阈值，不满意再请求更贵模型。论文还模拟判断器出错的概率 ε。级联可能在一题上调用多个模型，预测式路由一般只调用最终选中的模型。所以二者的实际请求成本和延迟结构不同。

## ⑤ 成本估计：算单价还是算一题真正的花费？

[原文，§5.1 和附录 A.1] 在预测式路由的**选择阶段**，作者用模型的每 token 定价近似成本，用于快速选模型；在**评价阶段**，数据记录了答案的真实调用成本，受输入/输出长度和定价影响。

不能把“模型定价”当作完全准确的“每题请求费用”。例如问一句选择题和输入长文档做 RAG，输入 token 不同，最终实际花费也可能不同。

这是一个值得留意的评测细节：**策略用来选模型的成本估计**与**最终报告成本的口径**必须分开写。论文还为未来扩展延迟、吞吐等指标预留可能性，但此版本核心还是美元成本与质量。

## ⑥ 决策与评价：本篇最关键的内容

### 6.1 预测式路由的决策公式

[原文，§5.1]

\[
m^*(q)=\arg\max_m\left[\lambda\widehat P_m(q)-\widehat C_m\right].
\]

其中 λ（willingness to pay）控制你愿意为质量支付多少。比如教学示例：A 的预测成绩 0.8、近似成本 0.08；B 的预测成绩 0.6、成本 0.01。当 λ=0.2，A 得 0.08、B 得 0.11，选便宜的 B；当 λ=1，A 得 0.72、B 得 0.59，选质量好的 A。这说明**不同偏好对应不同路由器**，不能拿一个固定权重的点代表完整性能。

### 6.2 Zero router 到底是什么？

[原文，§3.2] **Zero router 是“不看题目内容的最优随机固定模型混合基线”**。例如一个便宜模型与一个昂贵模型构成两端，可以掷硬币按一定概率选二者，在期望意义下得到两端之间的成本—质量点。再根据所有单模型点构成非递减凸包，取成本相同情况下的最佳期望质量。

它并不是“总选最差模型”，也不是“随机均匀选一个模型”，**更不是 2026 年的 ZeroRouter 方法论文**。

### 6.3 Oracle 又是什么？

[原文，§4.4] Oracle 事先知道每道题每个模型的真实质量，选能给出最佳答案的模型；出现并列时，选其中最便宜的。这是带未来信息的理想参考，不是可部署路由算法。

- Zero router：**不知道这道题具体适合谁**，但知道各固定模型的总体成本—质量表现。
- 预测式 router：**只看到题目和训练经验**，尝试预测这道题适合谁。
- Oracle：**事先知道所有模型在这道题上的结果**，理论上当然更强。

### 6.4 为什么要凸包和 AIQ？

[原文，§3.1–§3.3] 改变 λ 后，每个路由器产生一组 `(平均费用, 平均质量)` 点。首先去掉可以被更省钱且质量不低的组合取代的点，得到**非递减凸包 NDCH**。再比较共同成本区间 `[c_min,c_max]` 上的曲线：

\[
\operatorname{AIQ}(R)=\frac{1}{c_{\max}-c_{\min}}\int_{c_{\min}}^{c_{\max}}Q_R(c)\,dc.
\]

**特别容易误解**：AIQ 的全名是 *Average Improvement in Quality*，但原文写出的公式本身是凸包曲线在共同成本区间上的**平均质量高度**，不是公式里已经减去 Zero router 的提升量。要比较“提升”需在同一成本区间比较 AIQ 差值或两条曲线。并且“随机混合得到线段”成立于期望值，并不保证每次请求都达到期望。

## ⑦ 新模型接入：论文究竟有无解决？

**没有给出以“新模型上线”为中心的算法和实验。** 若使用 kNN，新模型需要在相关历史题上有成绩；若使用专门预测器，新模型也需有训练或适配数据。具体需要多少、是否重训、如何挑题，没有通过新模型到达实验给出结论。[原文范围 + 推导]

因而 RouterBench 更适合在论文中承担**评测框架与基准**角色，而不是直接担当“少样本新模型接入”最新强方法的唯一主对照。

## ⑧ 实验结果：哪些结论必须带条件？

[原文，§5.3–§5.4] 预测式 kNN/MLP 在部分任务可以用更低成本达到较强单模型的表现，但**整体没有显著超过 Zero router**：MMLU、Winogrande 高于它；HellaSwag、GSM8K 相近；ARC-Challenge、MBPP 反而低于它。Oracle 与现有路由器仍存在明显差距。

级联在判断器误差较低时可能优于 Zero router；判断错误率增至较高水平（文中讨论 >0.2）则性能明显恶化。RAG 场景由于搜索工具差异更明显，预测与级联均出现有利于路由的结果；这与一般纯模型问答设置不能直接混为同一个结论。

**“最早证明路由有价值”不准确**：前面已有 FrugalGPT 等相关研究。RouterBench 的价值是把“是否比强静态混合基线好”制度化，而不是宣称发现路由概念。

## 逐项纠错清单（对旧笔记）

| 旧笔记说法 | 核验 | 更严谨的写法 |
|---|---|---|
| 11 个模型 | 不完整 | 11 个核心模型，RAG 另用 3 个联网检索模型 |
| 只描述 kNN/MLP | 漏了重要实验 | 还有非预测式级联、模拟判断器、Zero router 与 Oracle |
| 使用向量编码 | 基本正确 | 具体编码器型号正文未清晰指定，不补造 |
| AIQ 是曲线平均高度 | 正确但待细化 | 比较非递减凸包在共同成本区间的平均质量 |
| Zero router 是普通随机选择 | 错 | 最优静态随机模型混合基线 |
| Oracle 显示多数题可用便宜模型 | 有图支持，但范围有限 | 对特定数据/候选集合的后验上界，不是线上真实可达收益 |

## 阅读时值得记录的破题点（尚非已成立 gap）

**RB-1 [原文→待实验]：预测式路由不容易超过强静态混合基线。** 这提示论文方法不能只与“固定最强模型”比较。下一步：在同样的数据和价格体系下，同时报告 Zero router、具体 kNN/MLP、单模型与 Oracle，检查哪个数据集真正有可学的逐题互补性。

**RB-2 [推导→待实验]：预测成本与真实成本有偏差，可能改写路由选择。** 下一步：把真实逐题成本和固定单价代入同一个路由器，比较选择翻转比例和质量—成本曲线；不能预设一定改善。

**RB-3 [推导→待文献]：AIQ 凸包评价与离散候选点下的偏好对应不完全一致。** 下一步：明确目标是批量平均预算还是每条请求硬预算，再研究随机混合在业务约束下是否可行。不要将此直接写成论文错误。

## 老师可能追问

1. 为什么你要用 Zero router，而不是随机选择？回答：它是经过凸包优化的、不依赖题目内容的强基线，可以检验个性化选择是否真的有效。
2. Oracle 能部署吗？不能；它用到测试时不可得的各模型真实结果，只作事后上界。
3. AIQ 为什么比一个 accuracy 有信息？因为不同偏好会产生不同质量—成本点，单点无法反映整个权衡范围。
4. 你是否复现了 RouterBench？如果只是读取了数据和论文，应该说“理解评测设计/读取缓存”，不是“完整重跑所有模型生成及官方训练流程”。
