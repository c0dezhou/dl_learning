## 给老师讲时，先讲清这六件事

**RouterBench 先解决“怎么比较才公平”。** 不同路由器使用的模型、题目和价格不同，单看准确率很难判断谁更好。因此，它收集同一批题在多个模型上的回答质量和成本，建立统一的评测方法。论文用 kNN、MLP 展示最直接的预测式路由：把当前问题变成向量，根据历史题目预测各模型的表现，再结合价格选模型；也比较先问便宜模型、回答不合格再升级的级联。它最重要的作用是告诉我们，学出来的路由器是否真的超过了强静态混合基线，以及距离逐题知道正确答案的 Oracle 还有多远。[展开看](01_RouterBench_精读核验.md)

**RouteLLM 把问题收窄到“这次用强模型还是弱模型”。** 如果每道题都交给强模型，成本很高；只用弱模型又可能损失质量。作者利用人类偏好及增强数据，让路由器根据问题预测“强模型的回答更受偏好的概率”，再通过阈值决定交给哪一个。相似度加权排名、矩阵分解、BERT 和自回归分类器是四种备选实现，不是串起来的四步。它改的是强弱二选一的判断方式；这个概率不等于强模型答对的概率，也没有直接表示多花一美元能换来多少质量。[展开看](06_RouteLLM_精读核验.md)

**IRT-Router 给质量预测加入了题目与能力的结构。** 直接预测“选谁”很难解释，也难以利用一个未见过模型的信息。IRT-Router 分别编码题目和模型简介，把它们映射为题目难度、区分度和模型能力，再估计模型完成当前题目的表现，最后与成本一起打分。MIRT 和 NIRT 是两种能力建模方式：前者使用潜在能力向量，后者引入预定义能力及其相关性。新模型可以凭简介得到能力估计，但论文的新模型实验主要验证预测误差，不能把它讲成已经证明了加入新模型后的路由收益。[展开看](02_IRT-Router_精读核验.md)

**ZeroRouter 希望模型换了，题目预测器还能继续用。** 为了减少对固定候选模型的依赖，它先用历史测评学习一个共享能力空间，再训练网络从题目文本预测该题在空间中的参数。新模型做一套预先选好的锚点题，就能拟合自己的能力，并建立成本和延迟估计；用户请求到来时，系统预测各模型的质量、费用和时延，再按偏好选择。这里真正可迁移的是题目与模型相互匹配的表示方式。论文的新模型实验仍需 200 道锚点反馈，所以不能把题名中的 zero-shot 理解成完全不测试新模型。[展开看](04_ZeroRouter_精读核验.md)

**RADAR 同时考虑“选哪个模型”和“让它思考多久”。** 推理预算变了，同一个模型的质量和成本也会变，因此 RADAR 把“模型＋预算”当成一个候选配置，用标量 IRT 预测它在当前问题上的表现，再通过多目标标量化权衡质量与成本。新配置接入时，它还有一套自适应测试：根据当前能力估计选信息量大的题，看到回答后更新能力，再选下一题。自适应 profiling 是它与我们研究最接近的部分，但不是整篇论文的全部贡献；主实验的新配置校准使用约 5000 道题，也不宜笼统说成只测极少几题。[展开看](03_RADAR_精读核验.md)

**ICL-Router 把模型的答题历史交给一个训练过的 LLM 路由器。** 它不把每个候选模型只当成固定 ID，而是在同一组 500 道题上记录各模型的 Yes/No 表现，形成能力档案。当前问题与历史题目先转成向量，再经过投影输入 7B 路由器；作者先通过题目重建训练让路由器读懂这些向量，然后训练它预测各候选模型是否答对，最终选择预测成功率最高的一个。新增模型只需补自己的答题档案，不必重训整个路由器。这里的上下文学习建立在专门训练的路由器上，并不是随便给一个未经训练的聊天模型贴一份成绩单。[展开看](05_ICL-Router_精读核验.md)

## 把它们放在同一个研究问题里

这六篇可以按“看懂请求、认识模型、了解新模型、做出选择、评价结果”来比较，但这只是帮助理解的视角，不是六篇论文依次拼成的系统，也不代表严格的历史演进。RouterBench 提供评测基准与直接预测基线；RouteLLM 学强弱模型间的选择；IRT-Router 为质量预测加入能力结构；ZeroRouter 和 ICL-Router 用不同方式让模型变化后仍能路由；RADAR 扩展了候选配置，并用自适应测试校准新配置。

如果研究的是新模型只有有限测试反馈时如何接入，RADAR 的自适应测试是一个直接参照，ZeroRouter 的固定锚点和 ICL-Router 的固定档案也有比较价值。我们想进一步问的是：既然测试最终是为了路由，那么下一道题是否应该按“它有多大可能改变最终选择”来选，而不只按“它能让能力估计多准确”来选？

这是一个待验证的研究问题。判断它是否有价值，需要让几种选题方法面对相同的数据、模型池和反馈预算，并观察最终质量与成本，而不只比较能力预测误差。要先查清错选模型的原因，再试一个简单的决策导向选题方法；只有稳定超过随机选题及相应强基线，才值得扩展更复杂的方法。模型池变大后准确率上升，也不能单独证明接入方法更好。

考虑到单卡 8GB 的条件，可以优先利用离线逐题响应和评分矩阵做方法对照。这样能把算力花在路由与选题方法上，但它与从头部署论文全部模型、重新生成所有回答仍是不同的实验范围。

## 这些结果要连同指标一起讲

| 数值 | 准确的含义 |
|---|---|
| RouterBench AIQ | 在共同成本范围内，质量曲线的平均高度，不是单个测试点的准确率 |
| RouteLLM APGR = 0.802 | MT-Bench 上的平均性能差距恢复率，设置为 Arena+judge、MF；不是 80.2% 绝对准确率 |
| RouteLLM CPT(50%) = 13.40% | 恢复一半强弱质量差所需的强模型调用比例，不是美元成本比例 |
| IRT-Router 80.67% / 87.12% | α=0.8、MIRT 的 ID / OOD Performance，两组测试集不同 |
| RADAR 0.7513 | GPQA-Diamond ID 的 Hypervolume，不是准确率 |
| RADAR 1.31% | MATH-500 ID 达到 o4-mini/high 质量的90%所需的参考成本比例 |
| ZeroRouter 0.39 | 表2 Max-Acc 权重下的 Reward，不是39%准确率 |
| ICL-Router 76.30% | 五个 ID 基准的平均准确率，不是质量—成本曲线下面积 |

RADAR 还有一处需要核对表号：主表1的 MMLU/FRAMES ID Hypervolume 为0.8720/0.8762，附录表20的 ID 基线却是0.8609/0.8865，后两个值与主表3对应的 OOD 值一致。这里保留作者原始数字，不替作者解释成某一种确定原因。逐题使用真实测试结果的 Oracle 也只表示理想参照，不能作为可部署算法的效果来讲。

## 补充阅读：LLMRouterBench

[LLMRouterBench](https://aclanthology.org/2026.findings-acl.1881/) 与 RouterBench 是两篇不同论文。它覆盖400K+实例、21个数据集、33个模型和10个路由基线，同时比较性能优先与性能—成本路由。它报告的一个问题是模型召回失败：有些题只有某个候选模型能答对，路由器却没选中。这个现象值得用于诊断，但不能未经实验就归因于 profiling 选题不合理，也不能概括成所有复杂方法都无效。
