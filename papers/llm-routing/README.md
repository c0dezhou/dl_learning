# LLM 路由六篇：来一个 query 怎样选模型，新模型怎样接入

## 两条主线

六篇论文可以沿两条线来读，两条线共用同一条路由链路（见[统一记号](#统一记号)）。

- **主线 A：来一个 query，怎样选到最合适的模型？** 这是每篇论文自己的主问题：怎样预测各模型的质量、怎样估成本、怎样按偏好权衡。读懂 A，就读懂了整个路由领域。
- **主线 B：一个新模型上线，要测多少题、测哪些题，才能把它接进路由池？** 它只改 A 链路上的一环（模型表示），但我们的研究问题在它的尽头。

两条线的关系是：**B 为主、A 为骨架。** B 要回答“哪道测试题最值得测”，必须先知道路由器之后怎么用这个新模型，而那正是 A 的内容。

## 统一记号

每个路由器都在回答生成之前做同一件事：看到问题 $q$，给池里每个候选 $m$ 估一个质量和一个成本，按偏好合成一个分数，选最高的那个。六篇只是在这条链路的不同环节动了手：

**问题表示 → 模型表示 → 质量预测 → 成本估计 → 决策规则 → 评测**

| 记号 | 含义 |
|---|---|
| $\widehat P(q,m)$ | 候选 $m$ 在问题 $q$ 上的预期表现，0 到 1 |
| $y_{qm}$ | 实测的表现（训练标签） |
| $\widehat C(q,m)$ | 成本估计；只依赖模型时写成 $\widehat C(m)$ |
| $z_m$ | 模型表示：路由器“认识”一个模型靠的东西 |
| $\theta_m$；$a_q$、$b_q$ | IRT 中模型的能力；题目的区分度、难度 |
| $B$ | 新模型接入时愿意付出的测试反馈条数 |

决策规则统一写成

$$
m^*(q)=\arg\max_m\left[w\,\widehat P(q,m)-(1-w)\,\widehat C(q,m)\right],\qquad 0\le w\le 1,
$$

$w$ 越大越看重质量。各篇原文的权重符号方向不一：

| 论文 | 原文写法 | 和 $w$ 的关系 |
|---|---|---|
| RouterBench | $\lambda\widehat P-\widehat c$，$\lambda$ = 愿付价 | $\lambda$ 越大越看重质量，同 $w$ |
| RouteLLM | $\widehat p\ge\alpha$ 选强模型 | 没有成本项；$\alpha$ 越大越省钱 |
| IRT-Router | $\alpha\widehat P-\beta C$，$\alpha+\beta=1$ | $\alpha$ 就是 $w$ |
| ZeroRouter | $w_p\widehat P-w_c\widehat C-w_t\widehat T$ | 多了延迟项 $\widehat T$ |
| ICL-Router | $\arg\max\widehat P$ | 没有成本项，相当于 $w=1$ |
| RADAR | 线性式同 $w$；另有切比雪夫式 | 见 06 第 3 节 |

主线 A 关心这条链路的每一环怎样做得更好；主线 B 只关心其中一环：**模型表示 $z_m$ 从哪里来、要花多少条反馈。**

## 主线 A：来一个 query，怎样选模型

### 尺子

[01 RouterBench](01_RouterBench_精读核验.md) 定下了后面五篇都在用的比较规则：路由器要和**同预算下按固定概率混合几个模型**的 Zero 基线比，而不是和单个模型比；Oracle 只是事后上界；用 AIQ 给整条成本—质量曲线打分。它的核心发现是：kNN、MLP 这类最直接的预测式路由，没有稳定赢过 Zero。

### 质量预测怎么一步步变强

| 论文 | $\widehat P$ 怎么来 | 得到了什么 | 代价 |
|---|---|---|---|
| RouterBench | kNN：最近 $k$ 道旧题上的平均分；或 MLP | 最简单，可直接复现 | 没有稳定赢过 Zero 基线 |
| RouteLLM | 偏好胜率：强模型回答更受偏好的概率；MF 最好 | 数据覆盖到位时，MT Bench 上 APGR 0.802 | 只能二选一；只用 Arena 数据时 BERT 为 0.391，低于随机 |
| IRT-Router | $\sigma(a_q^\top\theta_m-b_q)$：题目难度、区分度 × 模型能力 | 可解释；ID 80.67%，略高于 RouterBench 式的 80.01% | Top-1 只有 2.72%，很少选中最优那个 |
| ZeroRouter | 多维 2PL，另训“题目文本 → 题目参数”预测器 | 新题无历史成绩也有坐标 | 前期要拟合 200 个旧模型的坐标系 |
| ICL-Router | 训练过的 7B LLM 读“题目向量 + 对错”成绩册，判 Yes/No | 平均准确率最高：ID 76.30%，比 EmbedLLM 高 2.14 个百分点 | 要训 7B 路由器，推理时处理长上下文 |
| RADAR | 一维 2PL：$\sigma(a_q(\theta_g-b_q))$ | 参数最少；GPQA-Diamond 上 Hypervolume 0.7513 对 IRT 基线 0.6942 | 一条能力轴可能表达不了领域互补 |

两条贯穿六篇的观察：

- **数据和输入表示往往比路由器结构更关键。** RouteLLM 换更大的路由器补不上数据覆盖，ICL-Router 换更好的嵌入模型就涨约 2 个百分点。
- **平均分高 ≠ 逐题选对。** IRT-Router 平均性能领先，Top-1 却只有 2.72%。要用逐题后悔值 $U^*(q)-U_{\text{selected}}(q)$ 去量损失，而不是只看平均分。

### 成本和偏好怎么进入决策

| 论文 | 选模型时用的成本 | 评测时记的成本 | 决策规则 |
|---|---|---|---|
| RouterBench | 每 token 定价，每模型常数 | 逐题实际 token 费用 | $\lambda\widehat P-\widehat c$ |
| RouteLLM | 不算 | 强模型调用比例 | 阈值：$\widehat p\ge\alpha$ 选强模型 |
| IRT-Router | 归一化输出单价，每模型常数 | 逐题实际输入、输出费用 | $\alpha\widehat P-\beta C$ |
| ZeroRouter | 逐题：预测输出长度 × 单价；另估延迟 | Reward（三组权重） | 整批加权效用，可加总成本、总延迟约束 |
| ICL-Router | 不算 | 不算 | $\arg\max\widehat P$ |
| RADAR | 每配置在训练题上的平均输出成本（含思考 token，不含输入） | Hypervolume、CPT(90%) | 线性，或加权切比雪夫 |

- **切比雪夫能选到线性够不着的点。** 线性加权只能落在前沿的凸包上；切比雪夫看“离理想点最远的那一维”，能选到凹部配置。但它并非处处更好，例如 LSAT 上 0.9146 对线性的 0.9165。
- **单条预算和批量预算不是一回事。** Zero 基线的概率混合、ZeroRouter 的整批约束，满足的都是批量平均预算。若每条请求都不能超预算，结论可能不同。
- **曲线指标和单点指标。** AIQ、Hypervolume、APGR 对整条曲线打分；Reward、平均准确率只说明“在这组偏好下”谁更好。

### 主线 A 留下的问题

这些问题单独做成新路由器，增益往往很难做大；但它们决定了“路由器之后会怎么用一个模型”，所以会成为主线 B 研究的组成部分。下面都是待验证的问题，不是作者已证明的缺陷。

| 问题 | 出处 | 可以怎么检验 |
|---|---|---|
| 平均分高，逐题却很少选对 | IRT-Router 的 Top-1 只有 2.72% | 算逐题后悔值，看损失是均匀的近似并列，还是集中在某类任务 |
| 偏好胜率与实际收益错位 | RouteLLM 的 $\widehat p$ 不含钱，也不是答对率 | 90% 概率只改善格式的题，与 60% 概率避免严重错误的题，比较付费优先级 |
| 常数成本与逐题成本 | RouterBench、IRT-Router、RADAR 选模型时都用常数 | 固定质量预测器，只换成本口径，看决策翻转比例和曲线 |
| 单条预算与批量预算 | Zero 基线和 ZeroRouter 的约束都是批量的 | 先定业务约束，再判断随机混合、凹部点是否适用 |
| 阈值随流量漂移 | RouteLLM 的阈值要在代表性流量上校准 | 按时间或领域切片，看同一阈值下强模型调用比例的变化 |

## 主线 B：新模型怎样接入

主线 A 里，路由器靠模型表示 $z_m$ 来“认识”每个候选。新模型上线时，它没有历史成绩，$z_m$ 从哪里来？要花多少条反馈，又该测哪些题？六篇沿这个问题排成三站，RouterBench 不处理接入，但它是做接入实验的评测框架。

```mermaid
flowchart TD
    A["起点 · 尺子<br/>01 RouterBench<br/>逐题缓存 · Zero 基线 · Oracle · AIQ"]
    B["第 1 站 · 零反馈<br/>02 RouteLLM：换一对强弱模型<br/>03 IRT-Router：凭简介映射出能力 θ"]
    C["第 2 站 · 固定题单<br/>04 ZeroRouter：200 道 D-optimal 锚点题<br/>05 ICL-Router：500 题对错成绩册"]
    D["第 3 站 · 边测边选<br/>06 RADAR：按当前 θ 挑 Fisher 信息最大的题"]
    E["我们的问题 · 决策导向选题（待验证）<br/>下一题挑最可能改变路由选择的那道"]
    A -- "新模型没有历史成绩怎么办？" --> B
    B -- "猜不准，那就让它做几道题" --> C
    C -- "让前几题的答案决定下一题" --> D
    D -- "直接对准最终的路由选择" --> E
```

| 站 | 论文 | 新模型的 $z_m$ 从哪里来 | 这一站留下的问题 |
|---|---|---|---|
| 第 1 站：零反馈 | 02 RouteLLM | 不需要：只区分强/弱 | 只能二选一，说不清新模型擅长什么 |
| 第 1 站：零反馈 | 03 IRT-Router | 模型简介 → 25 维 $\theta$ | 新模型预测 AUC 只有 0.62，也没报告路由收益 |
| 第 2 站：固定题单 | 04 ZeroRouter | 200 道 D-optimal 锚点题拟合 20 维 $\theta$ | 选题去掉了 $p(1-p)$，不看新模型答得怎样 |
| 第 2 站：固定题单 | 05 ICL-Router | 500 道分层固定题的 Yes/No 记录 | 题单规则是手工的，也不随答题结果调整 |
| 第 3 站：边测边选 | 06 RADAR | Fisher 信息逐题选题拟合 1 维 $\theta$ | 优化的是“估得准”，不是“选得好” |

两个最值得记住的数字：同为 200 题，ZeroRouter 的 D-optimal 选题 Reward 为 0.39、随机选题为 0.27，说明**选哪些题确实影响接入效果**；RADAR 在 5,000 题时 Fisher 与随机基本持平，作者强调的优势在小预算下。

## 研究问题：B 为主、A 为骨架

主线 B 三站走下来，选题目标从“不测”到“覆盖能力方向”再到“让能力估计最准”，但都没有直接对准路由本身。我们要问的是：**给定接入预算 $B$，下一道题是否应该挑那道最可能改变最终路由选择的题？**

“估得准”和“选得好”为什么会分开：

- 新模型又贵又弱，在任何 $w$ 下都不会被选中。把它的 $\theta$ 估得再准也没用，最好的策略是早停、拒绝接入。
- 新模型只在某类低成本题上恰好压过旧池的最优者。要紧的只是它在这条决策边界附近的能力。

**为什么离不开主线 A。** 要算“这道题会不会改变选择”，先得知道路由器怎样选：用什么 $\widehat P$、什么成本 $\widehat C$、什么偏好 $w$。同一个新模型，准确率优先时可能在难题上与旧池最强者争位，成本敏感时可能在简单题上与便宜模型争位，两种情况该测的题不同；成本用常数还是逐题估计，同样会移动这条边界。论点可以写成一句话：**一道测试题对新模型有多大价值，取决于路由器之后怎么用它。**

**相邻工作与新意。** 目前查到的相邻工作都没有做“部署前、有预算、按路由决策挑测试题”，但这只说明空白可能存在，还需要系统查新：

- [RouteProfile](https://arxiv.org/abs/2605.00180)（2026.05）：只用模型卡、公开榜单分数等公开信号给新模型建画像，不做测试，接入时不重训路由器。它是 IRT-Router“凭简介”这条路的加强版，可作零反馈的强基线。
- [StageRoute](https://arxiv.org/abs/2506.17254)：在线 bandit 设定，新模型靠真实流量探索，给出后悔界。它与“部署前用设计好的探测题”是不同设定，但后悔值的定义可以借鉴。
- 评测侧的 tinyBenchmarks、Fluid Benchmarking 也在挑少量题测模型，但目标是估准总分，不是服务路由决策。

**验证时要守住的几条：**

1. **同台比较**：同一份离线逐题缓存、同一模型池、同一预算 $B$，比较随机、D-optimal（04）、固定分层题单（05）、Fisher 自适应（06）和决策导向选题。
2. **看路由结果**：报告 Zero 基线之上的 AIQ 或路由后悔值 $U^*(q)-U_{\text{selected}}(q)$，$\theta$ 的 RMSE 只作辅助。
3. **画预算曲线**：$B$ 取 16、32、64、200 等多个点。
4. **先诊断再加方法**：先查错选来自能力估计、成本近似还是题目参数，再试最简单的决策导向规则；只有稳定超过随机和 Fisher，才值得做复杂版本。
5. **防信息泄漏**：选题算法只能读已“购买”的反馈，测试标签只用于事后记分。
6. **固定候选池**：加入新模型本身会抬高上限，准确率上升不能单独证明接入方法更好。

**先做一个两到四周的小实验，再决定写不写。** 在 RouterBench 或类似的逐题响应矩阵上，轮流留出一个模型当“新模型”；预算取 16、32、64、200；比较随机、D-optimal、Fisher 和一个最简单的决策导向规则；指标用接入后的路由后悔值。单卡 8GB 条件下，全部基于离线逐题响应和评分矩阵做，不重新生成回答。增益在小预算下清楚且稳定，才值得投入写论文。

**论文路线：先会议，再期刊。**

1. **会议论文**只做 B：一个路由目标、一两个数据集，证明决策导向选题在小预算下稳定优于 Fisher 和 D-optimal。
2. **期刊扩展**加入 A 的维度：多种路由目标（准确率优先、成本敏感、偏好）、逐题成本、更大的基准（如 LLMRouterBench）、在线到达设定和理论分析。这些正好对应“主线 A 留下的问题”那张表。扩展需要多少新内容，要看目标期刊的规定和导师的意见。

一开始就按期刊写，范围容易铺得太开，最后没有一个结论够硬。

## 数字怎么读

跨论文的数字不能直接比大小，只能在同一张表、同一场景内比。

| 数字 | 实际含义 | 不是 |
|---|---|---|
| RouterBench AIQ | 共同成本区间内质量曲线的平均高度 | 某个点的准确率 |
| RouteLLM APGR = 0.802 | MT Bench 上恢复强弱质量差的平均比例（Arena + 裁判数据，MF） | 80.2% 准确率 |
| RouteLLM CPT(50%) = 13.40% | 恢复一半质量差所需的强模型调用比例 | 美元成本比例 |
| IRT-Router 80.67% / 87.12% | $\alpha=0.8$、MIRT 的 ID / OOD Performance | 同一测试集上的两个数 |
| ZeroRouter 0.39 | 接入实验 Max-Acc 权重下的 Reward | 39% 准确率 |
| ICL-Router 76.30% | 五个 ID 基准的平均准确率 | 质量—成本曲线 |
| RADAR 0.7513 | GPQA-Diamond ID 的 Hypervolume | 准确率 |
| RADAR 1.31% | MATH-500 ID 达到 o4-mini/high 九成质量所需的参考成本比例 | 绝对准确率 |

Oracle 只表示事后理想参照，不能当作可部署算法的效果。RADAR 还有一处表号疑点（主表 1 与附录表 20 的 ID 数值不一致），见 [06 第 6 节](06_RADAR_精读核验.md#6-容易读错的地方)。

## 补充阅读（只看它们的选题或接入方法即可）

- [Universal Model Routing for Efficient LLM Inference](https://arxiv.org/abs/2502.08773)（ICLR 2026）：把未见过的模型表示为它在一组代表性提示上的预测特征，与 ICL-Router 的成绩册思路最接近。
- [RouteProfile](https://arxiv.org/abs/2605.00180)（2026.05）：用公开信号给冷启动的新模型建图结构画像，零反馈一端的最新做法。
- [StageRoute / Keeping Up with the Models](https://arxiv.org/abs/2506.17254)：在线部署与路由的 bandit 方法，新模型靠真实流量探索。
- [tinyBenchmarks](https://arxiv.org/abs/2402.14992)（2024）：用 IRT 挑少量题估计模型在整个基准上的表现，是“用哪些题测准新模型”的评测侧代表。
- [Fluid Language Model Benchmarking](https://arxiv.org/abs/2509.11106)（2025）：把 IRT 自适应测试用在语言模型评测上，可与 RADAR 的 Fisher 选题对照。
- [LLMRouterBench](https://aclanthology.org/2026.findings-acl.1881/)（2026，与 RouterBench 是两篇不同论文）：400K+ 实例、21 个数据集、33 个模型、10 个路由基线。它报告的“模型召回失败”（某些题只有一个候选能答对，路由器却没选它）可用于诊断错选，但不能未经实验就归因于 profiling 选题不当。
- ZeroRouter 和 ICL-Router 都以 MODEL-SAT 作为动态接入基线，做实验时值得列入对照。
