## 第二部分：一眼记住六篇分别做什么

| 论文 | 它直接优化/研究什么 | 学模型能力要靠什么 | 新模型接入反馈 | 是否随反馈改变下一题 | 最关键评测 |
|---|---|---|---:|---|---|
| RouterBench | 建立公平的质量—成本路由评测框架 | 训练题上的成绩 / 预测器 | **无专门接入协议** | 不涉及 | AIQ、Zero router、Oracle |
| **RouteLLM** | 用人类偏好预测强模型胜率、二元阈值路由 | Arena 人类偏好 + 任务内/裁判数据增强，四种路由模型 | **直接换强弱模型对；无需对新模型额外做题建档** | 不涉及 | CPT(50/80%)、APGR、模型对迁移 |
| IRT-Router | 质量估计 + 固定成本打分 | 模型简介 → 25 维 θ | **0 题，靠简介构造表征** | 不涉及 | 性能/美元/Reward，新模型预测 MAE/AUC |
| RADAR | 模型 × 推理预算的多目标路由 | 配置 × 题目成绩 → 标量 θ | **主设置约 5000 题/新配置** | **是，Fisher** | Hypervolume、CPT、接入前后 |
| ZeroRouter | 质量 + 逐题成本 + 延迟路由 | 200 模型校准出的共享空间，新模型 200 anchors | **200 题/新模型** | 否，预先 D-optimal | 三权重 Reward、动态替换 |
| ICL-Router | 只根据成绩选最可能答对的模型 | 同一 500 题的 Yes/No 成绩档案 | **500 题/新模型** | 否，预先规则抽取 | ID/OOD 准确率、模型增长、消融 |

**三条必须永远分清的线**：

1. **预测得准 ≠ 路由收益高**：特别是 IRT-Router 的新模型实验。
2. **采集能力信息最多 ≠ 新模型对旧池的实际增益最大**：这是在 RADAR、ZeroRouter、ICL-Router 上均值得考察的*研究假设*，不是现已证明的普适漏洞。
3. **候选池扩大之后准确率提高 ≠ 新接入算法优于最简单接入策略**：还需对照相同新模型、相同反馈数和相同最终目标。

| A4 | ZeroRouter 一次从 10 个核心模型里选 | 10 个分成两个分开验证的 5 模型池 | ZeroRouter 表 1 |

### B. 概念与实验终点的混淆

| ID | 旧稿隐含问题 | 现在的修正 |
|---|---|---|
| B1 | RouterBench 只看 kNN/MLP | 它首先是**评测框架论文**；级联、Zero router、Oracle 非常重要 |
| B2 | RouterBench 的 Zero router 等于纯随机路由 | 它是**最优非递减凸包上的静态模型随机混合**，比随便随机更强；也不是 ZeroRouter 方法 |
| B3 | IRT 的新模型实验说明实际接入后效果提高 | 原文只验证新模型**成绩预测**（如 MIRT MAE 0.43），没有报告加池路由收益 |
| B4 | RADAR 的 5000 题是新模型“零样本接入” | 实际需要新配置回答真实问题，且每个新预算配置分别估 θ |
| B5 | RADAR 的 Fisher 与 ZeroRouter 的 D-optimal 是同一选题法 | 前者**逐题更新 θ 并重新选题**；后者提前固定不看新模型答案 |
| B6 | ICL-Router 输出 8 token，所以总路由成本等于 8 token | 输出 token 少不代表处理 500×8 档案向量的 7B 前向开销为零 |
| B7 | Max Expert 等于 Oracle | Max Expert 是**每个数据集最好的一款固定模型**；Oracle 是**逐题事先知道结果** |
| B8 | RADAR 每个基准所有指标都优于对照 | MATH-500 ID Hypervolume：RouterBench 0.9528，RADAR 0.9449 |
| B9 | RouteLLM 的“新模型接入”与 ZeroRouter 的 B 条反馈校准相同 | RouteLLM 是**固定二元路由器换模型对而不重训**，不曾构建新模型 B 条锚点能力档案 |
| B10 | RouteLLM 的 `P(win_s)` 是强模型做对题目的概率 | 它是人类/裁判**成对偏好胜率**，不是二分类正确率或预期绝对质量收益 |

| ID | 可以确定的部分 | 不能直接确定的部分 |
|---|---|---|
| C1 | IRT MIRT 论文公式 `aᵀθ−b`、正文 BERT 编码 | 旧稿说“BERT 冻结”和“a 通过 softplus 非负”；需核对仓库实际实现 |

### 额外的原文内部疑点

**RADAR 的主表与附录存在不一致**：主表 1 中 MMLU ID Hypervolume 是 **0.8720**、FRAMES ID 是 **0.8762**；但附录表 20 的“ID RADAR 基线”分别为 **0.8609** 和 **0.8865**。后两个值恰好等于表 3 的对应 OOD 基线值。可能是表格混用了 ID/OOD，**但未经过作者确认，不能自行篡改原始表格**。答辩中引用时必须写清表号和指标。

另一个常见错误是把“RADAR 有 Oracle”理解成 Oracle 的效率可以实操。它使用测试题上已知真实回答结果，是性能潜力边界，不是上线算法。

## 第四部分：怎么把五篇串成传统 ML 研究路线

**阶段 1：研究必要性与评测标准（RouterBench）**

先问：不同模型在逐题正确性上是否真的互补？在合理价格预算下，实际学出来的路由器是否比**强静态混合**更好？如果连这个都没有，设计复杂网络缺少必要性。

**阶段 1.5：直接学习“何时值得多花钱”（RouteLLM）**

使用 Arena 人类偏好训练路由器，阈值控制强模型调用比例；从四种模型的消融结果学习：训练数据覆盖与标签构造对路由效果可能比模型越大越好更重要。它的强项是双模型成本路由，弱点不是“泛化能力为零”，而是**不直接描述多模型池中新模型的个体能力和 B 条接入反馈**。

**阶段 2：建立可预测的关系结构（IRT-Router、RADAR）**

从「题目 × 模型成绩表」抽象出能力、难度、区分度；将高维隐表示换成可解释结构。IRT-Router 用模型简介来预测新模型，RADAR 用少量真实测试来估 θ。这里的核心问题是**建模假设与表示方式**。

**阶段 3：新模型如何接入（ZeroRouter、ICL-Router、RADAR）**

模型池不停更新，而路由网络训练很贵。不同论文提供三种建档法：通用空间+200 固定信息题；7B 阅读 500 道成绩册；标量 IRT + 5000 道 Fisher 自适应题。需要考虑的共同单位是**每个新到达模型的 profiling 预算**。

**阶段 4：问“为什么这些测试值得做”（拟研究问题）**

这些论文主要用 θ 后验拟合、Fisher/D-opt 信息量或旧模型答题分歧来设计试题，但部署时我们最终需要决定的是：“是否让新模型进入候选集合、在什么问题/价格条件下交给新模型？”

可把核心假设写成：**在已有旧池与明确的最终路由效用函数下，优先测试那些可能改变最优选择的题，可能比仅以全局能力参数估计精度为目标的测试策略更省反馈，并达到更好的部署效用。**

这只是候选假设，至少需要如下验证，而不是直接包装为已解决的 gap：

- **同数据、同模型池、同预算**下复现或重实现 RADAR Fisher、ZeroRouter D-optimal、ICL 固定题单以及随机选题；明确哪些实现使用公开缓存，哪些是在替代环境运行。
- **诊断真实痛点**：新模型是否经常“不值得接入”？信息量大但对路由决策完全无关的锚点占比是多少？最终 regret 的来源是能力水平估错、能力形状估错、成本估错，还是旧池在某些题上全错？
- **小试**：先使用一个非常简单的决策边界采样启发式，以少量反馈预算做统一对照；不胜过强基线就不要急着设计复杂 RL 或 BO 模块。
- **完整实验**：跨模型到达事件、随机反馈种子、不同旧池规模、成本权重，以及拒绝接入/自适应停止等重要消融；选定测试集之前锁定方法和超参数。

如果目标是在相对有限的 GPU 上完成硕士开题与方法论文，**先用离线评分矩阵完成方法级对照**比从头托管所有 35 配置的推理更合理。但这是一种资源选择，不等于完成了原作者的“整机端到端复现”。

## 第五部分：你要牢记的“不可横比”数值

| 一个数字 | 它是什么 | 不是什么 |
|---|---|---|
| RouterBench `AIQ` | 同成本范围上凸包平均质量高度 | 单个测试准确率，也不是某算法的提升百分比 |
| RouteLLM `APGR=0.802` | MT-Bench 的平均强弱性能差距恢复率（Arena+judge、MF） | 80.2% 绝对准确率 |
| RouteLLM `CPT(50%)=13.40%` | 恢复 50% 强弱质量差所需的强模型调用比例 | 13.4% 的绝对美元费用 |
| IRT-Router `80.67%` | 其 ID Performance（α=0.8、MIRT） | OOD 分数 |
| IRT-Router `87.12%` | 其 OOD Performance（α=0.8、MIRT） | ID 分数 |
| RADAR `0.7513` | GPQA-Diamond ID Hypervolume | 单题或平均准确率 |
| RADAR `1.31%` | 达到 o4-mini/high 质量的 90% 所需参考成本比例（MATH-500 ID） | 只有 1.31% 绝对准确率，也不是 90% 绝对准确率 |
| ZeroRouter `0.39` | 表 2 Max-Acc 加权 Reward（新模型 200 锚点） | 39% 原始正确率 |
| ICL-Router `76.30%` | 5 个 ID 基准的平均准确率 | 质量—成本曲线下的面积 |

## 第六部分：补充校对 LLMRouterBench（原稿中的第六个引用）

原笔记末尾对 **LLMRouterBench** 的简述也进行了公开原文核对：[arXiv:2601.07206](https://arxiv.org/html/2601.07206)，亦见 [Findings of ACL 2026 正式页面](https://aclanthology.org/2026.findings-acl.1881/)。

- **400K+ 实例、21 个数据集、33 个模型、10 个路由基线**：原文支持。
- 同时覆盖只看性能和性能—成本两类路由范式：原文支持。
- 统一评测发现不少复杂算法没有稳定胜过简单基线，且距逐题 Oracle 仍有明显差距：原文支持，但不等于“所有方法都无效”。
- 该研究强调的问题之一是**模型召回失败**：某些题只有一个候选模型能答对，路由器却没选它。这与主动校准和模型候选池构成有关系，但不能自动归因于“profiling 的选题方法不对”。

**注意**：LLMRouterBench 是原稿中附带的评测参考，和 RouterBench (2024) 是两篇不同论文。这里做了核心事实核对，但没有在本套“六篇方法/基准重点精读笔记”里把它冒充第六篇完整八环节精读。
